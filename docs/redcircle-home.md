# 红圈 club 首页 / 2026-11-16

## 范围
本次只升级对外首页与活动回顾管理。内部会员 ID、OpenID 关联、战力值 skillPoints、魅力值 rewardPoints、已有报名与荣誉数据不重置。不更改仓库名、微信主体或注册隐私文本的法律主体。

首页：品牌 Banner（红圈 club；智力竞技、兴趣社交、青年共创；深圳市南山区）→ 常驻数值隔离提醒 → 六类活动产品及介绍 → 已发布的近期活动 → 真实往期回顾 → 会员快捷入口。地址仅使用用户已提供的区级信息，不编造门牌、地图坐标或营业时间。

六类初始产品文案存放在 miniprogram/utils/club-home.js，可继续增加和修改。产品类型不等于已经排期的场次。旧活动暂按标题关键词匹配；以后可由活动创建表单明确选择 productId。

## 常驻强提醒
home、profile、ranking 都引用同一模板 miniprogram/templates/value-rule.wxml，不能在界面关闭。内容为俱乐部产品规则，不是法律合规认证：筹码（店内积分）、战力值、魅力值不得互换；魅力值不得因扑克输赢、筹码或战力值转换/联动获得；仅独立社区贡献规则可产生魅力值。此版本不新增任何兑换、发分或筹码转分代码。

## 回顾管理
新增云函数 activityRecaps（含 index.js、memberLookup.js、package.json）和管理页 pages/admin-recaps/index。入口：我的 → 活动回顾管理。

直接复用 activities 集合的 recap 子字段，无需新集合。管理权限通过服务端微信身份解析；普通会员不能编辑，门店管理员不能编辑其他门店活动。每次写入检查 recap.revision，避免并发覆盖；保存操作人、确认信息与时间。会员身份不接收客户端伪造字段。

发布必须关联已有、已发布且开始时间已过去的活动，管理员还必须明确确认活动实际结束，以及照片公开展示的必要同意；选择1–3张 JPG/PNG/WebP 图片（界面限制每张≤5MB）。测试开关默认开启，测试回顾不展示首页。只有明确关闭测试开关并发布的真实回顾才展示。下架回顾不删除原活动或报名。

图片放 activity-recaps/<服务端给定归属标识>/，保存云文件ID；服务端只为已发布、非测试回顾的该目录图片生成临时URL，不开放全桶读写。URL短期有效；下架不等于追回已下载/已缓存的图片。替换或上传失败留下的孤立文件需后续按留存规则清理。生产前还需内容审核、服务端文件体校验/大小限制、照片撤回渠道和索引/容量评估。

## 部署
1. git pull --ff-only origin main；出现冲突先保留本地修改，不强制覆盖。
2. 新部署 cloudfunctions/activityRecaps 整个目录，选择云端安装依赖。既有 activityAdmin / activityMember 这次未改，不需重部署。
3. 继续保持 activities、members、member_identities 仅管理端可读写；云存储权限也不需改为全员写。若上传失败检查当前用户的合法上传规则，而非开放所有数据。
4. 编译，首页应在没有回顾数据时显示真实空状态。回顾加载失败会单独提示，不阻断品牌、活动类型、会员区。
5. 我的 → 活动回顾管理，先用测试开关验证保存/下架；只有真实活动和获同意的照片才关闭测试开关发布。
6. 上传新小程序版本并设为体验版，普通体验成员重新进入测试首页与照片预览。

## 验收
- 三个页面均能看到完整的强提醒。
- 首页 Banner 标题和地址准确，六类介绍可筛选、可进入相关活动。
- 近期活动来自真实 activities 数据，无硬编码日期、人次和虚构热闹照片。
- 未发布/已取消/未来活动/测试回顾不出现在往期回顾；普通账号不能调用管理操作。
- 每次只展示近期回顾最多8条，管理列表最多100场；后续规模扩大再分页，不声称无限量历史。
- 这次更新不改变微信公众平台的小程序名称；平台名称需在公众平台另行设置。
