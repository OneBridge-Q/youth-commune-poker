# 红圈 club：魅力值规则入口与双榜

## 产品规则
- 首页不再展示整块重要规则，个人中心、天梯页也不重复大段警示。规则模板只由 `pages/charisma/index.wxml` 引用。
- 首页会员区点击「魅力值 ›」，或「我的 → 我的魅力值」，进入独立的魅力值页面。页面常驻红色规则提示，内容沿用原规则，没有新增筹码、战力值与魅力值转换功能。
- 天梯页面顶部两个页签：**战力值榜**（长期累计，不周期清零）和**魅力值榜**（自然季度重新统计）。战力值可随实际计分规则更新，不等于永久冻结。
- 自然季度按北京时间：1—3月、4—6月、7—9月、10—12月；服务端在新季度首日00:00自动切换统计区间。不是从注册日计算90天，不依赖用户手机时间，也不靠删除数据来重置。
- **本季魅力值**：季度内有效贡献获得值，叠加有依据的纠错调整。**可兑换余额**：继续读取 `members.rewardPoints`。两者分开：兑换消费不降低季度排名，换季不清空余额。
- 例：本季获得100点，兑换使用40点，则本季排名分仍为100、余额为60；换季后新一期分从0开始，余额仍为60。这里只说明规则，本次没有新增发放/兑换操作。
- 每榜展示前100位，同分并列（1、1、3）；当前用户不在前100也单独计算自己的名次。无有效分数时显示空榜，不生成示例数据。

## 代码范围
新增只读云函数 `memberRankings`：包含 index.js、service.js、policy.js、memberLookup.js、package.json。已有注册、头像、活动、荣誉云函数未改。没有修改会员ID、OpenID、skillPoints或rewardPoints数据。

请求示例：`{board:'battle'}` / `{board:'charisma'}`。必须是已注册且未停用的会员登录；不接受客户端指定当前日期、会员身份、分数或季度。返回只有榜单昵称、分值、排名及本人标记；不返回其他会员内部ID、OpenID、余额或身份信息。`rankVisible:false`、`isTest:true`、非active且非缺省status的成员不参与排名。现阶段头像未加入榜单，避免扩大会员图片访问。

战力榜读取 `members.skillPoints` 的正数值，不按季归零。当前还没有新增战绩评级算法，不能声称已自动从所有牌局计算战力。

## 魅力值季度数据源
新集合 `charisma_ledger`，**仅管理端可读写**。当前只提供读榜逻辑，不提供客户端写分或后台随意发分功能；没有真实记分流水时季度榜为空。

约定字段：
- `_id`：稳定幂等事件ID，未来由可信发放服务分配；不是用新时间戳重复发同一笔奖励。
- `memberId`：永久内部会员ID。
- `periodKey`：如 `2026-Q4`，以事件有效时间、北京时间自然季度计算。
- `effectiveAt`：数据库 Date，真实计分有效时间，不是字符串。纠错记入原事件所属期间，需保留证据。
- `status: 'posted'`、`isTest: false`：仅已入账、明确非测试的事件计入。
- `source` 仅支持 `activity_organization`、`knowledge_sharing`、`volunteering`、`community_contribution`。
- `kind: 'earn'`（rankingDelta必须>0）或 `kind: 'adjustment'`（非零纠错）；`rankingDelta` 应为有限整数，未来写入服务需校验。
- `redeem`、`redemption_refund`、牌局胜负、筹码/战力转换来源均不计入季度榜。

用服务端聚合按 memberId 累加 rankingDelta 后，关联 members 排名。历史余额没有可靠来源时间，不自动灌入本季；历史流水不删除。旧季度数据保留，但此版本暂不提供历届榜浏览、季度快照或结算奖励。发放/扣减/兑换、幂等校验与完整审计是后续独立任务，须与余额修改在事务中一起落账。

建议规模扩大前增加 `charisma_ledger(status, isTest, periodKey, effectiveAt, memberId)` 索引，核查部署环境的索引建议和聚合性能。页面与我的排名使用多次只读聚合，高并发写分时并非同一数据库快照；正式赛季结算应使用冻结快照，而非依赖即时榜。

## 部署与验收
1. `git pull --ff-only origin main`。保持已有会员数据，不清库。
2. 云开发 → 数据库 → 新建 `charisma_ledger`，权限「仅管理端可读写」。保持空集合即可；不要为填满榜单伪造真实分数。
3. 上传部署整个 `cloudfunctions/memberRankings` 目录，选择云端安装依赖；不用重部署旧云函数。
4. 编译，确认首页Banner后不再出现规则；点击首页魅力值可进入规则页，「我的」也有入口。
5. 天梯切换两榜，检查累计榜文案、季度起止日期、本人成绩、空状态；点击魅力值规则链接能进入同一页面。未注册者显示注册提示，不泄露榜单。
6. 上传并设置新的体验版后，再由普通体验成员检查。

## 本地验证
执行 `node scripts/test-member-rankings.cjs`。使用模拟云数据库和独立测试数据，不连接真实环境。覆盖并列排名、前100与本人名次、身份隔离、退款/兑换/测试记录过滤、自然季度边界、跨年切换及余额保留。通过本地测试不代表云开发聚合、真机和权限配置已验收。
