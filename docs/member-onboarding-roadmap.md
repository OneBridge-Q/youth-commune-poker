# V0.4 会员自主注册（首次交付）

## 已实现
- 微信小程序入口：未注册用户可从首页或「我的」进入 `pages/register/index`。
- 用户明确输入昵称（2–16 字符）并勾选注册说明后，云函数 `memberRegister` 才写入 `members`。
- 服务端从微信云环境获取 OpenID；客户端不能指定 `_openid`、角色、积分、门店或会员编号。
- 已注册用户再次提交不会覆盖原档案或管理员权限。
- 新会员默认 role=member、积分 0、待评级；试运营固定属于 store-001。
- 使用 SHA-256(OpenID) 的稳定摘要生成文档 ID 与会员编号。与历史手工创建的 YC000001 不冲突，编号目前不承诺连续。
- 首次创建用数据库只插入操作，加上确定性 _id 处理并发重复注册；正式运营前仍需压测与安全审计。

## 部署
1. 更新小程序代码，确认 app.json 包含 register 页面。
2. 确认数据库已有 members 集合，集合权限限定管理端读写。
3. 右键 cloudfunctions/memberRegister → 上传并部署：云端安装依赖。
4. 当前超级管理员已手工注册，不能用其账号测试新用户注册。请让一个已经添加为体验成员的新微信用户预览，在首页点击「立即加入」。
5. 完成注册后，返回首页确认昵称和编号，再进入「我的」查看会员编号；管理员用昵称搜索确认可找到这个新会员。
6. 再次打开注册页提交（或直接调用函数）应返回 alreadyRegistered=true，不应重复创建 members 数据。

## 正式运营前的必要工作
- 发布正式隐私保护指引，说明处理目的、保存期限、联系渠道、信息更正及注销办法，并与微信小程序后台隐私配置一致。
- 对用户昵称展示和后台检索实施内容安全/风控。
- 建立会员注销/更正、反滥用限流与操作日志机制。
- 多门店上线时，不应再将新会员统一分配到固定 store-001。
- 活动报名、签到、成长积分另行实施；不得把积分与赌博/有价输赢挂钩。


## 2026-11-15 更新：微信头像与昵称快速填写
- 注册表单采用 `button open-type="chooseAvatar"` 与 `input type="nickname"`，用户可主动选择微信头像和昵称，也可自行输入，不能静默获取微信公开资料。
- 头像可不选；选择后由客户端调用 `wx.cloud.uploadFile` 上传至 `member-avatars/`，只将持久化的 `avatarFileID` 存入 `members`，而不是保存临时路径。
- 服务端 `memberRegister` 仅接受受限的云文件 ID；已有会员调用 `action: "updateProfile"` 可更改昵称与头像，不能改角色、积分、OpenID 或会员编号。
- 首页、个人中心通过 `wx.cloud.getTempFileURL` 获取可展示头像链接。已注册用户在「我的」→「编辑头像与昵称」维护资料。
- 部署：更新小程序，并**重新部署已有的** `memberRegister` 云函数；无需新建数据库集合。
- 真机验证：昵称候选和头像选择在模拟器里可能与真实微信表现不同，需使用真实微信体验版测试。
- 正式发布前补全用户隐私保护指引、资料删除、头像滥用管理、历史云存储文件清理与服务端安全检测。头像昵称属个人信息，提供跳过头像的选项，不应要求用户必须使用微信个人头像。
